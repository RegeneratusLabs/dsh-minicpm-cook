# MiniCPM cook

[English](README.md) · **中文**

为 OpenBMB **MiniCPM** 系列模型准备的实用手册，专为 AI 编程助手设计。

直接问你的助手："这个任务、这张显卡，我该微调哪个 MiniCPM？" 它会给出训练方案、
可直接运行的配置文件，以及许可证条款 —— 而不是让你翻五个文档页面。

---

## 为什么需要它

OpenBMB 公开的材料其实很多：一个文档站、每个模型一份微调指南、十种推理框架的部署
说明，还有一份单独的多模态模型手册。质量都不错。

问题在于，它们是**按模型**组织的，而你的问题是按任务提出的。

- *哪个 8B 多模态模型支持 vLLM，而且训完之后允许我再分发？*
- *单张 24 GB 显卡够用吗，还是得上四张？*
- *我这份训练数据到底能不能用，会不会白白烧掉六个小时？*
- *发布一个微调模型，许可证要求我附带哪些文件？*

回答这些问题，需要在四个仓库之间来回对照，还要记住每个库的哪个版本支持哪个模型。
本项目把这些信息整理成一份目录，和七个助手可以直接调用的工具。

## 你可以这样问它

安装之后，下面这些都是普通对话：

> 用 MiniCPM5-2B 做 SQL 生成微调，我只有一张 RTX 4090。

→ 它会选择 LoRA，估算约 7 GB 显存，生成带正确损失掩码的 TRL 脚本，并列出需要
满足的依赖版本。

> 我这份数据集能用吗？

→ 检查 JSONL：有没有缺失的助手回复、角色顺序是否错乱、图片路径是否存在、有没有
悄悄超出上下文长度的样本。

> 用 vLLM 部署 MiniCPM-V 4.6。

→ 给出启动命令、针对你的上下文长度估算的显存占用，以及一条验证服务正常的 `curl`。

> 这个微调模型能发布到 Hugging Face 吗？

→ 先核对许可证，然后生成模型卡、`NOTICE` 文件和上传命令；如果许可证未确认，它会
直接拦住，并告诉你缺什么。

## 安装

插件就是一个本地文件夹，不需要从包管理器安装。

1. 克隆仓库：

   ```bash
   git clone https://github.com/RegeneratusLabs/dsh-minicpm-cook.git
   ```

2. 在 DeepSeek Harness 中打开 **Plugins → Add plugin**，选择
   `dsh-minicpm-cook/plugin` 文件夹。

3. 开一个新会话，问一个相关的任务。

也可以用命令行安装：调用插件管理器的 `install_bundle` 动作，参数填该文件夹的绝对路径。

你同样可以只把它当作参考资料使用：所有事实都存放在
[`data/models.json`](data/models.json) 里，[`docs/`](docs/) 下的指南也可以独立阅读
（中文版见 [`docs/zh/`](docs/zh/)）。

## 七个工具

| 工具 | 它能帮你做什么 |
| --- | --- |
| `minicpm_catalog` | 列出全部模型，按参数量、模态、许可证或推理框架筛选 |
| `minicpm_plan` | 把目标和显卡情况变成一份有先后顺序、带显存估算的方案 |
| `minicpm_recipe` | 生成可直接运行的 TRL、LLaMA-Factory 或 ms-swift 配置 |
| `minicpm_check_dataset` | 找出那些会让你白烧显卡时间的数据问题 |
| `minicpm_doctor` | 对照模型要求检查你这台机器 |
| `minicpm_serve` | 给出部署命令和一条冒烟测试请求 |
| `minicpm_publish` | 准备模型卡、署名文件和上传命令 |

另外还有四个技能（skill），助手会在需要时自行加载：分别对应选模型、微调、部署、发布。

## 支持的模型

共 17 个模型，从 1B 的手机端模型到 35B-A3B 的多模态模型。

| 系列 | 规模 | 适合什么 |
| --- | --- | --- |
| MiniCPM5 | 1B、2B | 端侧小助手，也是最容易微调的一档 |
| MiniCPM4.1 / 4 | 0.5B、8B | 端侧推理任务，带稀疏注意力 |
| MiniCPM-SALA | 8B | 超长文档（百万 token 上下文） |
| MiniCPM-V 4.7 / 4.6 | 1B、8B、35B-A3B | 图片、文档与视频理解 |
| MiniCPM-o 4.5 | 9B | 语音与视觉同时输入输出的实时交互 |
| MiniCPM-OCR | 8B | 文档解析，附带一个结果校验模型 |

完整的表格 —— 许可证、上下文长度、支持哪些推理框架 —— 见
[`docs/models.md`](docs/models.md)。

## 需要说明的边界

- **它本身不训练、也不部署。** 它生成方案和配置，由你来执行；你不主动调用，它不会
  占用任何显卡。
- **显存数字是估算值。** 来自一个公开的计算公式，界面上都标注了"估算"。实际占用会
  有出入。
- **17 个模型中有 5 个标注为"未核实"**，并写明了需要确认的地方。许可证无法确认时，
  发布会主动拦截。
- **上游更新很快。** OpenBMB 在 2026 年发布了五个模型。运行 `npm run drift` 可以查看
  本仓库是否已经落后。

## 参与贡献

```bash
npm run validate   # 校验模型目录的结构与一致性
npm test           # 40 个测试，不联网、不需要显卡
npm run render     # 由目录数据重新生成 docs/models.md
npm run drift      # 与 OpenBMB 官方仓库比对
```

关于模型的每一条事实都存放在 `data/models.json`，并附带来源链接。新增模型只需
添加一条记录，校验脚本会告诉你还缺什么。
